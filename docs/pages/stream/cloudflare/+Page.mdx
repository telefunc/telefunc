## Setup

```ts
// worker.ts
// Environment: server

import { Telefunc } from 'telefunc/cloudflare'

const telefunc = new Telefunc()

export const TelefuncDurableObject = telefunc.TelefuncDurableObject

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const response = await telefunc.serve({ request, env, ctx })
    if (response) return response

    return new Response('Not found', { status: 404 })
  },
}
```

> Fundamentally, channels are stateful: the server holds live state for each open channel. Cloudflare Workers, however, are stateless and ephemeral — any request can be served by any worker, and nothing is remembered between requests. The state therefore needs to live somewhere else — Durable Objects and KV are Cloudflare's primitives for exactly that:
>
> - **Durable Objects** provide stateful compute: each channel lives on a Durable Object, which holds the connection and its state.
> - **KV** provides shared storage: it's how stateless workers find the Durable Object that holds the state, no matter which worker a request lands on.
>
> The Durable Object and KV bindings are required whenever you use `telefunc/cloudflare`. If your app doesn't use `Channel`, `Broadcast`, or `Room`, you can skip these bindings and use <Link href="/serve"><code>serve()</code></Link> instead.
>
> See <Link href="#architecture" /> for implementation details.

> **Upgrading from a key-value-backed `TelefuncDurableObject`:** earlier releases declared it with `new_classes`. Cloudflare can't change an existing class's storage backend, so [re-provision it](https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/): delete the class, then declare it again as a SQLite class. Its state is lost in between; Broadcast sequence numbers restart at 1.

## Architecture

Telefunc uses [Durable Objects](https://developers.cloudflare.com/durable-objects/) for <Link href="/channel">channel</Link> state and <Link href="/channel#broadcast">broadcast</Link> fan-out. Channel state is in-memory JavaScript (closures, callbacks, local variables), so it must live on the same Durable Object that holds the WebSocket connection.

[KV](https://developers.cloudflare.com/kv/) stores session tokens, which pin a browser to the same Durable Object across requests.

### Regions

Telefunc maps each request to one of six geographic regions using Cloudflare's colocation data:

| Region | Code |
|---|---|
| West North America | `wnam` |
| East North America | `enam` |
| West Europe | `weur` |
| East Europe | `eeur` |
| Asia Pacific | `apac` |
| Oceania | `oc` |

Each region runs its own Durable Objects so that channel state stays close to users.

### Session affinity

Every telefunction call and channel message from a client must reach the **same Durable Object** — otherwise that client's channel state would be unavailable.

On the first request, Telefunc returns a session token to the client via the `x-telefunc-session` header. The token picks one Durable Object of the nearest region, and KV remembers that region for it (TTL: 24 hours). Subsequent requests send the token back, so they reach the same Durable Object, even after the KV entry lapses while the client stays in that region.

<Warning>

**CDN / reverse proxy** — make sure `x-telefunc-session` isn't stripped from responses or requests. Without it, each request would be routed to a random Durable Object and channel state would be lost.

</Warning>


### Room state

Each logical <Link href="/room">room</Link> has one authority, a `TelefuncDurableObject` instance of its own, holding the room's head, members, ordering watermarks, retained generations, and live delivery routes in SQLite. A directory instance backs `Room.list`. Room writes and reads therefore go through the room's authority; they don't use a Broadcast authority or a Workers KV room-state mirror.

Room calls such as `Room.create()`, `Room.announce()` and `Room.close()` work anywhere in your Worker, including cron triggers and queue consumers. Server-side listeners (`subscribe()`, `onJoin()`, …) deliver to a Telefunc session, so install them inside a telefunction or a channel handler.

| State | Storage | Consistency |
|---|---|---|
| Room head, roster, ordering, retained messages | The room's authority Durable Object (SQLite) | Strongly consistent |
| `Room.list` directory projection | The directory Durable Object (SQLite) | Repairable projection, verified against the room head |
| Broadcast sequence numbers and presence | The key's authority Durable Object (SQLite) | Strongly consistent |
| Session affinity | Workers KV | Eventually consistent |

## Scaling

By default, Telefunc creates one Durable Object per region. Increase capacity with `scale`:

```ts
const telefunc = new Telefunc({ scale: 4 })
```

This creates 4 Durable Objects per region, and Telefunc distributes sessions across them.

### Per-region scale

```ts
const telefunc = new Telefunc({
  scale: { weur: 5, enam: 3, apac: 2 },
})
```

Only specified regions get Durable Objects. Requests from unspecified regions fall back to <Link href="#configuration">`locationFallback`</Link>.


## Distributed broadcast

<Link href="/channel#broadcast">Broadcasts</Link> fan out across all regions automatically.

`publish()` works anywhere in your Worker, including cron triggers and queue consumers. A server-side `subscribe()` delivers to a Telefunc session, so subscribe inside a telefunction or a channel handler.

### How it works

<Advanced>

You can skip this section — it's Telefunc's internal fan-out, not anything you configure.

</Advanced>

```
Publisher (Durable Object)
  → Authority DO (one per key — assigns sequence numbers)
    → Coordinators (one per active region)
      → Durable Objects (deliver to local subscribers)
```

1. The publisher forwards the message to an **authority** Durable Object for the key.
2. The authority assigns a monotonic sequence number, reads the key's presence from its own storage, and forwards to each region with subscribers.
3. Each region's coordinator fans out to the Durable Objects in that region.
4. Each Durable Object delivers to its local subscribers.

### Ordering

<Link href="/channel#broadcast">Broadcast</Link> publishes for a given `key` go through a single authority, which assigns a <Link href="/channel#broadcast">monotonic `seq`</Link>. Every subscriber receives them in `seq` order: the authority forwards them in that order, and each hop sends through one Durable Object stub, whose calls Cloudflare delivers in the order they were made. Publishes from one session reach the authority in the order they were made.

### Presence

Each key's authority records which Durable Objects have subscribers, in its own storage:

| Setting | Value |
|---|---|
| TTL | 90 seconds |
| Refresh | every 30 seconds |

A Durable Object registers with the authority on its first subscription to a key and withdraws on its last unsubscribe. A subscription is ready once the authority has recorded it, so every publish sequenced after that reaches it. If a Durable Object is evicted (e.g. during a deployment), its record lapses after 90 seconds and fan-out skips it.


## Delivery guarantees

### Channel messages (`send` / `listen`)

| Guarantee | Details |
|---|---|
| Ordering | Messages are delivered in order. |
| Buffering | The server buffers messages while the client is disconnected: up to `config.channel.bufferLimit` for text (default: 512 KB) and up to `config.channel.bufferLimitBinary` for binary (default: 2 MB). Binary frames have a separate budget and can never evict text. |
| Replay | Both sides keep a replay buffer. On reconnect, missing messages are replayed and duplicates are ignored. |
| Acknowledgements | `send(data, { ack: true })` resolves when the other side processes the message. |
| Loss | If the disconnection lasts longer than `config.channel.reconnectTimeout`, the channel closes with <Link href="/channel#errors">`NetworkError`</Link>. |

### Broadcast messages (`publish` / `subscribe`)

| Guarantee | Details |
|---|---|
| Ordering | Every subscriber receives a key's publishes in `seq` order. |
| Delivery | `publish()` resolves once the key's authority has handed the message to every Durable Object with subscribers. Delivery is at-most-once: one that fails to take it loses it, and the loss is logged. Delivery to clients then happens over the channel connection. |
| Subscription | A subscription is ready once the key's authority has recorded it; every publish sequenced after that reaches it. |

> Once a broadcast message reaches a Durable Object, it has the same buffering and replay guarantees as regular channel messages.


## Configuration

```js
const telefunc = new Telefunc({
  bindingName: 'TelefuncDurableObject',  // DO binding name (default)
  kvBindingName: 'TelefuncKV',           // KV binding name (default)
  instanceName: 'telefunc',              // Base name for DO instances (default)
  scale: 1,                              // DOs per region (default)
  locationFallback: 'weur',              // Fallback region (default)
  jurisdiction: 'eu',                    // Restrict DOs to a jurisdiction (optional, no default)
})
```

## Hibernation

> **[Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/#why-use-hibernation) while channels are open isn't supported.**
>
> Channel state is in-memory JavaScript. If the Durable Object hibernates, that state is gone. Telefunc keeps the Durable Object alive while channels are open.

The Durable Object can hibernate once all channels are closed, no clients remain connected, and both the reconnect and idle windows have expired.

```ts
import { config } from 'telefunc'

// Shorter windows = hibernate sooner, less disconnect tolerance
config.channel = {
  reconnectTimeout: 5_000,
  idleTimeout: 5_000,
  pingInterval: 2_000
}
```
