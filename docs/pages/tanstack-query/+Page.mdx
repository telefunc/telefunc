Live queries for [TanStack Query](https://tanstack.com/query) — when a telefunction returns a <Link href="/drizzle">`Live`</Link> value, wrap it with `live()` and the query stays current on its own: the server signals that the result is stale, and the query refetches.

<PoweredByTelefuncStream pkg="tanstack-query" />

## Install

```bash
npm install @telefunc/tanstack-query
```

That's it — there is nothing to register. `live()` is imported where you use it.


## Usage

Pass the telefunction — and its arguments — to `live()`, and use it as an ordinary `queryFn`:

```tsx
import { useQuery } from '@tanstack/react-query'
import { live } from '@telefunc/tanstack-query'
import { onGetTodos } from './Todos.telefunc'

function Todos({ userId }) {
  const { data: todos } = useQuery({
    queryKey: ['todos', userId],
    queryFn: live(onGetTodos, userId), // onGetTodos(userId) returns a Live<Todo[]>
  })
  // ...
}
```

`data` is the value itself (`Todo[]`), not the live handle — the wrapper unwraps it.

> This wraps the `queryFn`, not the hook, so it works unchanged with the React, Vue, Solid and Svelte adapters.

The server side is <Link href="/drizzle">`@telefunc/drizzle`</Link>: `onGetTodos` ends its query with `.live()`, and a write through the same reactive db invalidates exactly the queries that read the changed rows.

#### Pass the telefunction directly

```js
// ❌ Broken: the abort signal never reaches the request
queryFn: live(() => onGetTodos(userId))

// ✅ Pass the telefunction and its arguments
queryFn: live(onGetTodos, userId)
```

> TanStack Query cancels an in-flight fetch by aborting a signal, and `live()` attaches that signal to the call it issues. A wrapper closure calls the telefunction outside that window, so cancellation would silently do nothing. This is caught at runtime rather than left to fail quietly.


## Cleanup

Each live query owns a subscription for as long as its entry is in the query cache. When the entry is removed — `removeQueries()`, or TanStack Query's own garbage collection — the subscription is closed. A refetch replaces the handle and closes the previous one. Nothing to unsubscribe by hand.


## How it works

1. The `queryFn` calls the telefunction, which returns a `Live<T>` handle.
2. The wrapper unwraps `.data` for the cache and subscribes to the handle's stale signal.
3. On a write, the server invalidates the affected live queries; each connected client holding one receives the signal.
4. The wrapper calls [`invalidateQueries()`](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys) for that key, TanStack Query refetches, and a fresh handle replaces the old one.

> Staleness drives a **refetch** — rows are not pushed into the cache. The client re-reads through the telefunction, so <Link href="/permissions">authorization</Link> applies to every refetch exactly as it did to the first read.
