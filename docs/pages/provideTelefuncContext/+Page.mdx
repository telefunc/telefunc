**Environment**: server.

`provideTelefuncContext()` makes the `context` object available to telefunctions (via <Link href="/getContext">`getContext()`</Link>) — useful when a telefunction runs **outside `telefunc.serve()`**, such as server-side rendering or unit tests.

```ts
// Environment: server

import { provideTelefuncContext } from 'telefunc'

const { todoItems } = await provideTelefuncContext({ user }, () => onLoad())
// getContext() inside onLoad() returns { user }
```

`provideTelefuncContext(context, fn)` calls `fn` and returns what `fn` returns: call your telefunction inside `fn` (e.g. in your test or your SSR request handler).

> If the telefunction calls `getContext()` after an `await`, add `import 'telefunc/async_hooks'`, see <Link href="/getContext#access" />.

> With `import 'telefunc/async_hooks'`, you can also call `provideTelefuncContext(context)` without `fn`: it provides `context` to the code that runs after it.

> With <Link href="/serve">`serve()`</Link> / <Link href="/Telefunc">`new Telefunc()`</Link>, the context is provided for you — see <Link href="/getContext#provide" />. Reach for `provideTelefuncContext()` only when a telefunction runs outside both.
