The `@telefunc/media` package adds calls to a <Link href="/room">room</Link>: participants publish their camera, microphone or screen and play each other's, and your server can send and read audio and video too.

## Install

Media builds on <Link href="/room#install">Room</Link>, so install both:

```bash
npm install @telefunc/room @telefunc/media
```

That's it: your participants get `publishMedia()`, `sendMedia()` and `subscribeMedia()`.

> Telefunc finds `@telefunc/*` packages in your `package.json` and auto-loads them. For TypeScript to know the methods, import the package in one file of your app: `import '@telefunc/media'`.

## Make a call

Return the room and your participant from a telefunction, as for any <Link href="/room#create-and-join-a-room">room</Link>:

```ts
// Meeting.telefunc.ts
// Environment: server

import { getContext } from 'telefunc'
import { Room } from '@telefunc/room'

export async function onJoinMeeting(id: string) {
  const { user } = getContext()
  const room = await Room.getOrCreate(id)
  const me = await room.join({ meta: { name: user.name }, identity: user.id, selfDelivery: false })
  return { room, me }
}
```

Publish your camera and microphone, and play each other participant in a `<video>`:

```ts
// Meeting.ts
// Environment: client

import '@telefunc/media'
import { onJoinMeeting } from './Meeting.telefunc'

const { room, me } = await onJoinMeeting('standup')

const camera = await navigator.mediaDevices.getUserMedia({ audio: true, video: true })
selfView.srcObject = camera // your own picture is the stream you already hold
me.publishMedia(camera)

const show = (member) => member.subscribeMedia(tileOf(member)) // tileOf(): your <video> for this member
for (const member of await room.getParticipants()) show(member)
room.onJoin(show)
```

> A `<video>` plays its participant until they leave; `stop()`, on what `publishMedia()` or `subscribeMedia()` returns, stops earlier.

> To mute, disable the track: `camera.getAudioTracks()[0].enabled = false`.

Each viewer receives the picture at the resolution its `<video>` shows on screen, a lower one while their connection can't keep up, and no picture while the `<video>` is out of view. Your page sends no more than its connection to the server carries, so your sound never waits behind your picture.

## Share your screen

Publish it on a track of its own:

```ts
// Environment: client

const screen = await navigator.mediaDevices.getDisplayMedia()
me.publishMedia(screen, { track: 'screen' })
```

Each viewer hears of a participant's tracks with `onMedia()`. It fires for the tracks the participant publishes already, as you call it, and whenever one starts or stops:

```ts
// Environment: client

member.onMedia((track, on) => {
  if (track !== 'screen') return
  if (on) member.subscribeMedia(showScreenTile(member), { track }) // showScreenTile(): your <video> for this screen
  else hideScreenTile(member)
})
```

> `track` is `null` for what a participant published without a track, such as the camera above.

To show it to one participant only, send it as you <Link href="/room#send-a-private-message">send a private message</Link>. Only that participant's `onMedia()` hears of it, and they play it the same way:

```ts
// Environment: client

me.sendMedia(member, screen, { track: 'screen' })
```

## Show who speaks

```ts
// Environment: client

const playback = member.subscribeMedia(tile)
playback.onSpeakingChange((speaking) => tile.classList.toggle('speaking', speaking))
```

## Publish from the server

A participant your server joined, such as a voice assistant, publishes frames that are already encoded: say their `codec`, and write each frame.

```ts
// Assistant.telefunc.ts
// Environment: server

import '@telefunc/media'
import { Room } from '@telefunc/room'

export async function onStartAssistant(id: string) {
  const room = await Room.get(id)
  const assistant = await room.join({ identity: 'assistant', meta: { name: 'Assistant' } })

  // speechModel: your own, audio in and audio out
  const voice = assistant.publishMedia({ codec: 'opus' })
  speechModel.onSpeech((opus, startMs) => voice.write({ data: opus, timestamp: startMs * 1000 }))

  // What the others say, as encoded frames
  const hear = async (member) => {
    for await (const frame of member.subscribeMedia()) speechModel.hear(frame.data, frame.timestamp)
  }
  for (const member of await room.getParticipants()) hear(member)
  room.onJoin(hear)
}
```

> A frame is `{ data, timestamp, key }`: `data` is a `Uint8Array` holding one encoded frame (here, one Opus packet), `timestamp` is where it starts, in microseconds as in WebCodecs, and `key: false` marks a video frame that needs the frames before it. A frame you read also has its `codec` and its `kind`, `'audio'` or `'video'`.

Every frame you write arrives, in order. To stop mid-sentence, `voice.clear()` drops what the listeners haven't played yet, and `voice.onPlayout(({ member, playedUntil }) => …)` tells you how far each listener has heard: `playedUntil` is the `timestamp` of the last frame their page played.

> For a source whose newest moment matters more than every frame, such as a camera your server relays, publish with `{ codec: 'h264', lossy: true }`: a listener that falls behind skips to the newest keyframe. What a page publishes from a `MediaStream` is always sent that way.

> In the page, it needs [WebCodecs](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API) in the browser.

> With `@telefunc/webrtc` installed, a call of two goes over a direct link between the two pages, and through your server again once a third participant or your server's own code joins the call. To refuse a pair a direct link, throw in the room's <Link href="/room#room-guard-hooks">`onBeforeDirect()`</Link> hook.

> With <Link href="/webtransport" />, each participant's sound and each size of their picture travel on a stream of their own, so a lost packet of one holds back none of the others. On a WebSocket, it holds back every one.
