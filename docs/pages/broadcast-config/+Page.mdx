**Environment**: server.

```ts
// Environment: server

import { config } from 'telefunc'

config.broadcast = {
  transport: myTransport, // A BroadcastTransport that carries Broadcast across servers
  onDeliveryLost: (lost) => monitor.report(lost), // { key, reason } of messages a subscribed server never got; by default logged
}
```

`transport` is a `BroadcastTransport`:

```ts ts-only
type BroadcastTransport = {
  send(key: string, payload: string): { seq: number; timestamp: number } | Promise<{ seq: number; timestamp: number }>
  listen(key: string, onMessage: (payload: string, info: { seq: number; timestamp: number }) => void): () => void
  sendBinary(key: string, payload: Uint8Array): { seq: number; timestamp: number } | Promise<{ seq: number; timestamp: number }>
  listenBinary(key: string, onMessage: (payload: Uint8Array, info: { seq: number; timestamp: number }) => void): () => void
}
```

> Without a `transport`, Broadcast uses the installed backend (such as <Link href="/redis"><code>@telefunc/redis</code></Link>) or, with none installed, stays in memory and reaches only subscribers on the same server. A configured `transport` takes precedence over both.

> `send()` and `sendBinary()` return the `{ seq, timestamp }` they assigned, and `onMessage` gets the same pair, which <Link href="/channel#broadcast">`Broadcast.subscribe()`</Link> subscribers receive as `info`. A key's `seq` increases with each message, across all servers and for text and binary together; `timestamp` is like `Date.now()`.

> `listen()` and `listenBinary()` return a function that stops listening. A message sent right after `listen()` returned must reach that listener.

> When its connection drops, the transport reconnects on its own and keeps calling the `onMessage` it was given.

> A transport that sends `sendBinary()`'s `payload` after `sendBinary()` returns (after an `await`, or from a queue) must send a copy: the publisher may reuse its buffer once <Link href="/channel#broadcast">`publishBinary()`</Link> returns.

> `onDeliveryLost` is called on the server (on Cloudflare, in the Durable Object) that missed the messages, and they aren't sent again. With `@telefunc/redis`, `reason` says how many it missed; on Cloudflare, that it may have missed some. Telefunc doesn't call it for a `BroadcastTransport`, as only the transport knows what it lost: have your transport report that itself.
