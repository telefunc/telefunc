Redis-backed <Link href="/channel#broadcast">broadcast</Link> fan-out across server instances — a `publish()` on any instance reaches every `subscribe()` on every other instance. <Link href="/room">Rooms</Link> work across instances too.

> You only need this if you scale horizontally — see <Link href="/stream/scale" />.

## Install

```bash
npm install @telefunc/redis ioredis
```

```ts
// Environment: server

import IORedis from 'ioredis'
import { installRedis } from '@telefunc/redis'

const redis = new IORedis('redis://localhost:6379')
installRedis(redis)
```

That single call installs the Redis backend for both Broadcast and Room. Room state and events are then shared across server instances. Make it before the first Broadcast or Room use, for example in a module your server entry imports first: a use before it starts the in-memory backend, and `installRedis()` then throws.

### Sharing an existing client

Pass an existing [`ioredis`](https://github.com/redis/ioredis) Redis or Cluster instance when you want to share a connection or set options such as TLS or authentication.

```ts
// Environment: server

import IORedis from 'ioredis'
import { installRedis } from '@telefunc/redis'

const redis = new IORedis(process.env.REDIS_URL, { tls: {} })
installRedis(redis)
```

Telefunc duplicates the supplied client as needed without disconnecting it, so you can continue to use it alongside Telefunc. Subscriptions share one duplicated connection; when it drops (a Redis restart, a failover), they resume on a fresh one. Messages published while it was down are lost, as delivery is at-most-once. A failover whose new master missed the last writes rewinds their sequence numbers: subscribers still connected then drop as many later messages as it lost, since delivery never goes back in order. When you remove a Cluster node (`redis-cli --cluster del-node`), shut it down too: a removed node left running keeps the subscribers connected to it, and they receive nothing until it stops.

Telefunc runs its commands on its own connection, duplicated from your client with retries off, so a command whose reply was lost can't execute twice. Your client keeps its options, and Telefunc's connection closes when your client does. Pub/Sub channels ignore an ioredis `keyPrefix`, so `installRedis()` throws for a client that sets one: pass `installRedis(redis, { prefix })` instead.

Room keeps its state (rooms, members, lane order) in Redis keys with no expiry, so Redis must never evict them: use `maxmemory-policy noeviction`, or a `volatile-*` policy, which evicts only keys with an expiry. An `allkeys-*` policy can silently break a room.

## Channels

`Channel` is per-instance. Reconnects must land on the instance holding the channel's state, so multi-instance deployments need sticky sessions at the load balancer. See <Link href="/stream/scale" />.
