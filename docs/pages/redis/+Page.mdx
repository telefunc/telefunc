Redis-backed <Link href="/channel#broadcast">broadcast</Link> fan-out across server instances — a `publish()` on any instance reaches every `subscribe()` on every other instance. <Link href="/room">Rooms</Link> work across instances too.

> You only need this if you scale horizontally — see <Link href="/stream/scale" />.

## Install

```bash
npm install @telefunc/redis ioredis
```

Requires Redis 5 or later.

```ts
// Environment: server

import IORedis from 'ioredis'
import { installRedis } from '@telefunc/redis'

const redis = new IORedis('redis://localhost:6379')
installRedis(redis)
```

That single call installs the Redis backend for both Broadcast and Room. Room state and events are then shared across server instances. Call `installRedis()` before your server first uses Broadcast or Room, for example in a module your server entry imports first. If Broadcast or Room is used before `installRedis()`, Telefunc starts its in-memory backend for that use, and the later `installRedis()` call throws.

### Sharing an existing client

Pass an existing [`ioredis`](https://github.com/redis/ioredis) Redis or Cluster instance to reuse its options, such as TLS or authentication.

```ts
// Environment: server

import IORedis from 'ioredis'
import { installRedis } from '@telefunc/redis'

const redis = new IORedis(process.env.REDIS_URL, { tls: {} })
installRedis(redis)
```

Telefunc duplicates the supplied client as needed without disconnecting it, so you can continue to use it alongside Telefunc. A subscriber misses the messages published while its connection to Redis is down (a Redis restart, a failover), as delivery is at-most-once. After a failover that lost the last writes, `seq` numbers can repeat. When you remove a Cluster node, shut it down too: subscribers connected to it receive nothing until it stops.

On a Redis Cluster, a reshard or a failover can delay a message by up to one second, so that subscribers still receive messages in the order they were published.

Pub/Sub channels ignore an ioredis `keyPrefix`, so `installRedis()` throws for a client that sets one: pass `installRedis(redis, { prefix })` instead. It also throws for a `prefix` that contains `{`.

Room keeps its state (rooms, members, lane order) in Redis keys that Redis must never evict: use `maxmemory-policy noeviction`. Any other policy can silently close a room.

Keep your Redis masters' clocks synchronized: message timestamps come from them, as does the moment a stopped server's rooms close and its members leave.

## Channels

`Channel` is per-instance. Reconnects must land on the instance holding the channel's state, so multi-instance deployments need sticky sessions at the load balancer. See <Link href="/stream/scale" />.
