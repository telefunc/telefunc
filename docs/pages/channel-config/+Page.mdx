**Environment**: server.

<TelefuncStreamBeta />

```ts
// Environment: server

import { config } from 'telefunc'

config.channel = {
  reconnectTimeout: 60_000,  // How long a client may be gone and get its channels back (ms)
  pingInterval: 5_000,       // How often a client pings; it counts as gone after twice this (ms)
  maxMemory: '4g',           // The most this server's channels hold for clients, all together (bytes, or a size)
}
```

> **You rarely need any of these.** A channel that awaits each `send()` before the next builds no backlog, whatever the client does. A publish waits for no subscriber, so a `BroadcastChannel` has <Link href="/channel#backpressure">limits of its own</Link>.

> - `reconnectTimeout`: a client that comes back within it finds its channels open, and gets the messages held for it. It never gets a `send()` refused past `maxMemory` or 320 MiB, or the oldest messages a `BroadcastChannel` dropped. Past `reconnectTimeout`, its channels close with `NetworkError`. Raise it for clients on bad networks. Lower it to free a gone client's channels sooner.
> - `pingInterval`: how fast a client that stopped answering counts as gone, which starts its `reconnectTimeout`. Raise it to save a phone's battery. Lower it to notice sooner.
> - `maxMemory`: a number of bytes, or a size such as `'4g'` or `'512m'`. It defaults to a quarter of the memory the process may use, so `'4g'` above is the default of a 16 GB machine. It counts what the server holds, not what clients hold. As the server nears `maxMemory`, the clients furthest behind a <Link href="/channel#new-broadcastchannel">`BroadcastChannel`</Link> miss their oldest messages first. At `maxMemory`, a `send()` rejects with `ChannelOverflowError`. That message isn't delivered, and the channel stays open. One channel holds at most 320 MiB, whatever `maxMemory` is. A single message larger than either limit is refused even if you await it. Lower `maxMemory` to use less memory. Below 128 MiB, it also slows large transfers to and from a distant client. A channel sends at most half of `maxMemory` per round trip, so the slowdown grows toward the 2 MiB minimum.

> On Cloudflare, `maxMemory` defaults to 64 MiB, as <Link href="/stream/cloudflare">a Durable Object's memory</Link> is limited to 128 MB.

> Telefunc refuses a value that can't work when you assign it: `reconnectTimeout` or `pingInterval` under 1 second, or `maxMemory` under 2 MiB. Assign `config.channel` before your server handles its first request: once a channel exists, a change is refused, as open channels would keep the old values.

> This is the **server-side** `config.channel`, a separate object from the **client-side** <Link href="/transport"><code>config.channel.transports</code></Link> (`telefunc/client`).
