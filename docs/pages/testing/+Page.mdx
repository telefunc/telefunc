**Environment**: server.

Telefunctions are plain functions — you can unit-test them by importing and calling them directly. No server, no HTTP, no mocking.

```ts
// hello.telefunc.test.ts
// Environment: server

import { onHello } from './hello.telefunc'

test('onHello', async () => {
  expect(await onHello('Eve')).toBe('Welcome, Eve')
})
```


## Providing context

If a telefunction reads <Link href="/getContext">`getContext()`</Link> (e.g. to get the logged-in user), call it inside <Link href="/provideTelefuncContext"><code>provideTelefuncContext()</code></Link>:

```ts
// Team.telefunc.test.ts
// Environment: server

import { provideTelefuncContext } from 'telefunc'
import { onJoinTeam } from './Team.telefunc'

test('rejects a non-member of the team', async () => {
  const context = { user: { id: 1, teams: [] } }
  const joining = provideTelefuncContext(context, () => onJoinTeam('acme'))
  await expect(joining).rejects.toThrow() // throws Abort()
})
```

> If your server imports `telefunc/async_hooks`, import it in your test as well: `getContext()` then also works after an `await`. Otherwise, call `getContext()` before any `await`, see <Link href="/getContext#access" />.

This is also how you test <Link href="/permissions">permissions</Link> — set up a context that should (or shouldn't) pass, then assert the telefunction returns or throws `Abort()` accordingly.


## Channels & the wire protocol

A telefunction that opens a <Link href="/channel"><code>Channel</code></Link> is still a plain function — call it directly to assert it authorizes correctly and wires up its listeners.

The wire protocol — reconnection, multi-client broadcast, transport upgrades — only exists over a real connection, so cover it with an **end-to-end test** against a running server.
