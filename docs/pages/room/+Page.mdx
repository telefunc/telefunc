`Room` adds multi-party **rooms** on top of <Link href="/channel">channels</Link>: presence, participant metadata, per-member streams, private messages, and admin controls. Use it whenever *who is connected* matters: chat, game lobbies, collaborative editing, live dashboards.

> When you only need a pipe to one client, use <Link href="/channel#new-channel">`new Channel()`</Link>. When you need pub/sub without membership, use <Link href="/channel#new-broadcastchannel">`new BroadcastChannel()`</Link>.

> For running multiple server instances, see <Link href="#deployment" />. For the room defaults, see <Link href="/room-config" />.


## Example

A telefunction hands out a room; the client joins, sees who's there, and chats:

```js
// Lobby.telefunc.js
// Environment: server

import { Room } from 'telefunc'

export async function onGetLobby() {
  return await Room.getOrCreate('lobby')
}
```
```js
// Lobby.js
// Environment: client

import { onGetLobby } from './Lobby.telefunc'

const lobby = await onGetLobby()

lobby.onJoin((who) => console.log(`${who.meta.name} joined`))
lobby.subscribe((msg, info, from) => console.log(`${from.meta.name}: ${msg.text}`))

const me = await lobby.join({ meta: { name: 'Alice' } })
await me.publish({ text: 'hello' })
```

Open it in two browser tabs and the first sees the second join and say hello.

There are three objects:

- **`Room`** is the shared space. You create and administer it on the server through the <Link href="#room-statics">`Room.*` statics</Link>; anyone holding the room object observes its members, events, and messages.
- **`LocalParticipant`** is you, returned by `join()`. You publish, send private messages, and set your metadata through it.
- **`RemoteParticipant`** is everyone else: subscribe to one member, watch their metadata, know when they leave.

> Return any of the three from a telefunction and use it on the client as on the server.


## Identity vs meta

Two fields describe a participant:

- **`meta`** is display state the participant sets on itself (`name`, `avatar`, `score`). Any client can set it to anything.
- **`identity`** is an app id (a user id) that the server sets at `join()`. It is trusted, immutable, and the same across a user's tabs and reconnects.

<Warning>Never authorize on `meta`: `from.meta.role` is whatever that client last set. Authorize on `identity`, checked against your own server-side data.</Warning>


## Presence

`room.snapshot()` returns the members, and `room.onChange()` fires whenever someone joins, leaves, or changes their metadata:

```js
room.onChange(() => renderRoster(room.snapshot().participants))
```

In React, the pair plugs into `useSyncExternalStore()`:

```jsx
// Environment: client

function useRoom(room) {
  return useSyncExternalStore(room.onChange, room.snapshot)
}
function Roster() {
  const { participants, count } = useRoom(room)
  return <>{count} online: {participants.map((p) => <Avatar key={p.id} {...p.meta} />)}</>
}
```

For one event at a time, use `room.onJoin()`, `room.onLeave()` and `room.onParticipantUpdate()` (see <Link href="#room" />).

`me.setMeta({ name: 'Alice', score: 42 })` replaces your metadata, and `me.setAttributes({ score: 42 })` merges it by key (a key set to `undefined` is removed). Every observer sees the change.


## Messages

`me.publish()` sends to the whole room. `room.subscribe()` receives every member's messages, and `member.subscribe()` one member's:

```js
room.subscribe((data, info, from) => showMessage(from.meta.name, data))
await me.publish({ text: 'hello' })

room.onJoin((member) => {
  const decoder = createDecoder()
  member.subscribe((data) => decoder.push(data))
  member.onLeave(() => decoder.close())
})
```

`from` is the sender, set by the server: a client can't fake it. Your own publishes reach your own subscribers too; turn that off with `join({ meta, selfDelivery: false })`, for example for video.

For high-frequency updates (cursors, live reactions), pass `{ coalesce: key }` on the client: while a publish with that key is in flight, newer ones collapse into one pending publish carrying the latest value:

```js
onCursorMove((pos) => me.publish({ pos }, { coalesce: 'cursor' }))
```

### TypeScript

Pass the message type as the third type parameter of `Room.create()`, `Room.get()`, or `Room.getOrCreate()`:

```ts
// Chat.telefunc.ts
// Environment: server

type ChatMeta = { topic: string }   // room.meta
type MemberMeta = { name: string }  // each participant's meta
type ChatMsg = { kind: 'chat'; text: string }
const room = await Room.get<ChatMeta, MemberMeta, ChatMsg>(roomId)
```

`publish()` and `subscribe()` are typed to `ChatMsg`, and Telefunc's <Link href="/shield">shield</Link> checks every client `publish()` against it at the server: anything else rejects with `ShieldValidationError` before a guard or a subscriber sees it.

> The shield checks the shape, not who may send it: authorize in a guard's `onBeforePublish()` (see <Link href="#moderation" />), which is also where JavaScript apps check messages.


## Direct messages

`send()` delivers to one participant, and `listen()` receives:

```js
// Alice
me.listen((data, from) => showDm(from.meta.name, data))

// Bob (by id, or by RemoteParticipant)
const { seq, timestamp } = await bob.send(aliceId, 'meet me in room 2')
```

For a reply, pass `{ ack: true }`: `send()` then resolves with the recipient handler's return value as `response`:

```js
const { response } = await bob.send(aliceId, { move: 'e4' }, { ack: true })
// Alice: me.listen((move) => (rules.check(move) ? 'ok' : 'illegal'))
```


## Moderation

`Room.guard()` attaches server-side checks to one room instance. Call it in the telefunction that returns the room, where <Link href="/getContext">`getContext()`</Link> is available:

```js
// Chat.telefunc.js
// Environment: server

import { Abort, getContext, Room } from 'telefunc'

export async function onJoinChat(roomId) {
  const { user } = getContext()
  const room = await Room.get(roomId)
  Room.guard(room, {
    onBeforeJoin: (member) => {
      if (member.identity !== user.id) throw Abort('join through onJoinChat()') // only the join below
      if (banned.has(user.id)) throw Abort('banned')
    },
    onBeforePublish: (from, data) => { if (isSpam(data)) throw Abort('blocked') },
    onBeforeSend: async (from, to) => { if (!(await areFriends(user.id, to.identity))) throw Abort('not friends') },
  })
  return { room, me: await room.join({ meta: { name: user.name }, identity: user.id }) }
}
```

The guards run on your own `join()` through that instance, and on every `join()`, `publish()`, and `send()` a client makes through it. `throw Abort(value)` in an `onBefore*()` guard rejects the caller with `value` as `err.abortValue`; any other error is a bug, see <Link href="/error-handling" />.

The `onAfter*()` hooks (`onAfterJoin()`, `onAfterPublish()`, `onAfterSend()`) run once the operation took effect, with its receipt: `{ seq, timestamp }`, or `{ joinedAt }` for `onAfterJoin()`.

> A join a client makes has `identity: null`, as only the server sets `identity`. So key your guards on the telefunction's own user, as above.

<Warning>Guards apply only to the instance passed to `Room.guard()`: other `Room.get()` calls return unguarded instances. Returning a room, or a `RemoteParticipant` of it, lets the client join through that instance.</Warning>

Remove a participant with a reason that arrives with the removal:

```js
await Room.removeParticipant(roomId, { id: participantId, reason: 'be nice' }) // one membership
await Room.removeParticipant(roomId, { identity: userId, reason: 'banned' })   // every tab of a user

// The removed client
me.onLeave((cause) => {
  if (cause.type === 'removed') showBanner(`Removed: ${cause.reason}`)
})
```

The room itself can speak, so that receivers can't mistake it for a member: `Room.announce()` reaches `onAnnounce()` (never `subscribe()`), and `Room.send()` reaches one participant's `listen()` with `from === null`:

```js
// Server
await Room.announce('lobby', { type: 'maintenance', in: '5min' })
await Room.send('lobby', { id: winnerId }, { badge: 'first-blood' })

// Client
room.onAnnounce((data) => showBanner(data))
me.listen((data, from) => (from === null ? showSystemNotice(data) : showDm(from.meta.name, data)))
```


## Hidden participants

A server that acts in a room, running a game loop or a bot, joins with `{ hidden: true }`:

```js
// Environment: server

const room = await Room.create(matchId, { emptyTimeout: Infinity, departureTimeout: Infinity })
const authority = await room.join({ identity: 'authority', hidden: true })
authority.listen((cmd) => world.apply(cmd)) // its return is the reply to a send() with { ack: true }
startGameLoop(matchId, authority)           // each tick: authority.publishBinary(worldState)
```

A hidden participant is a full `LocalParticipant` that is left out of presence: `count`, `getParticipants()`, `snapshot()`, `onJoin()`, `onLeave()`, and `onEmpty()` ignore it, and it doesn't keep the room open. So the match above turns both timeouts off, and you end it with `Room.close(matchId)` (see <Link href="#when-a-room-closes" />).

Only the server can join hidden. What a hidden participant publishes reaches every subscriber. To let a client talk to it, return it from a telefunction:

```js
// Match.telefunc.js
// Environment: server

import { getContext, Room } from 'telefunc'

export async function onJoinMatch(matchId, name) {
  const { user } = getContext()
  const room = await Room.get(matchId)
  const authority = (await room.getParticipants({ hidden: true })).find((p) => p.identity === 'authority')
  return { room, me: await room.join({ meta: { name }, identity: user.id }), authority }
}
```
```js
// Match.js
// Environment: client

const { response } = await me.send(authority, { type: 'move', to: 'e4' }, { ack: true })
authority.subscribeBinary((frame) => world.apply(frame))
authority.onLeave(() => showMatchAborted())
```


## Binary and tracks

`publishBinary()` and `subscribeBinary()` carry raw bytes: canvas deltas, audio snippets, file chunks. A participant can publish several named tracks (mic, camera, screen share); subscribe with `{ track }` to receive one, or without it to receive all. Per-frame `meta` arrives on `info.meta`:

```js
captureAndEncode(camera, (frame, isKey) => me.publishBinary(frame, { track: 'camera', meta: { key: isKey } }))

member.subscribeBinary((data, { meta }) => video.decode(data, { key: meta?.key }), { track: 'camera' })
```

Subscribe only to what you render: watching 9 of 500 cameras, subscribe to those 9 members, and the other 491 streams never reach you.

`onDemand()` tells a publisher whether anyone watches one of its tracks, so it can pause its encoder:

```js
me.onDemand((track, wanted) => {
  if (track === 'screen') wanted ? encoder.resume() : encoder.pause()
})
```

`{ retain: true }` keeps a message for subscribers that come later: the room's last retained `publish()`, and each publisher's last retained `publishBinary()` per track. Mark keyframes with it, so that a late subscriber can decode your deltas:

```js
me.publishBinary(keyframe, { track: 'camera', meta: { key: true }, retain: true })
```

<Warning>Rooms send binary over the same reliable, ordered connection as text (WebSocket or SSE). That fits data and small-scale audio/video, but not large-scale live video, which needs congestion control and simulcast: pair Rooms with a WebRTC SFU for that. See [telefunc#449](https://github.com/telefunc/telefunc/issues/449).</Warning>


## History

Rooms deliver live messages; keep history in your database. Store each message in `onAfterPublish()`, and use `Room.get(id, { tail: true })` so that the client receives what was published while you loaded the history:

```js
// Chat.telefunc.js
// Environment: server

import { getContext, Room } from 'telefunc'

export async function onJoinChat(roomId) {
  const { user } = getContext()
  const room = await Room.get(roomId, { tail: true })
  Room.guard(room, {
    onAfterPublish: async (from, message, info) => {
      await db.messages.insert({ ...message, roomId, authorId: user.id, seq: info.seq, at: info.timestamp })
    },
  })
  const history = await db.messages.latest(roomId, 50) // ordered by seq
  return { room, history }
}
```
```js
// Chat.js
// Environment: client

const { room, history } = await onJoinChat('lobby')
const me = await room.join({ meta: { name } })

const stored = new Set(history.map((m) => m.seq))
for (const m of history) render(m)
room.subscribe((data, info) => { if (!stored.has(info.seq)) render(data) })
```

Order messages by `info.seq`; `info.timestamp` is for display.


## Switching rooms

Membership is per room, so switching is `leave()` then `join()`:

```js
await current?.leave()
current = await nextRoom.join({ meta: { name } })
```

> A telefunction can return several rooms at once, such as `team` and `team:red`, each with its own members and guards.


## When a room closes

A room closes on its own once it's no longer used: `departureTimeout` (20 seconds by default) after its last member left, or `emptyTimeout` (5 minutes) if nobody joined it. Set them per room, or for every room with <Link href="/room-config">`config.room`</Link>:

```js
await Room.create('match-42', { emptyTimeout: 60_000, departureTimeout: Infinity }) // Infinity: until Room.close()
```


## Example: game lobby

Players join, ready up through their own `meta`, and the server starts the match once everyone is ready:

```js
// Lobby.telefunc.js
// Environment: server

import { getContext, Room } from 'telefunc'

export async function onJoinLobby(lobbyId, name) {
  const { user } = getContext()
  const room = await Room.getOrCreate(lobbyId)
  return { room, me: await room.join({ meta: { name, ready: false }, identity: user.id }) }
}

export async function onReadyUp(lobbyId) {
  const players = await Room.getParticipants(lobbyId)
  if (players.length < 2 || !players.every((p) => p.meta.ready)) return
  if (await db.lobbies.claimStart(lobbyId)) await Room.announce(lobbyId, { type: 'start' }) // once per lobby
}
```
```js
// Lobby.js
// Environment: client

const { room, me } = await onJoinLobby('room-42', 'Alice')

room.onChange(renderRoster)
room.onAnnounce((e) => { if (e.type === 'start') startGame() })
room.onLeave(() => void onReadyUp('room-42'))

onReadyClick(async () => {
  await me.setAttributes({ ready: true })
  await onReadyUp('room-42')
})
```

## Reference

### Room statics

Server-side. A client gets a room when a telefunction returns it.

| Method | Returns | Throws |
|---|---|---|
| `Room.create(id, options?)` | `Room` | If the room already exists |
| `Room.get(id, { tail? }?)` | `Room` | If the room doesn't exist |
| `Room.getOrCreate(id, options?)` | `Room` | - |
| `Room.guard(room, hooks)` | `void` | - |
| `Room.join(id, options?)` | `LocalParticipant` | If the room doesn't exist |
| `Room.list({ prefix? }?)` | `RoomInfo[]` | - |
| `Room.setMeta(id, meta)` | `void` | If the room doesn't exist |
| `Room.setAttributes(id, attributes)` | `void` | If the room doesn't exist |
| `Room.close(id)` | `void` | - |
| `Room.removeParticipant(id, target)` | `void` | For `{ id }`: missing room or unknown participant |
| `Room.announce(id, data)` | `{ seq, timestamp }` | If the room doesn't exist |
| `Room.send(id, target, data)` | `void` | If the room doesn't exist; for `{ id }`: unknown participant |
| `Room.getParticipants(id, target?)` | `ParticipantSnapshotView[]` | If the room doesn't exist |

```ts
type RoomOptions = {
  meta?: Record<string, unknown> // Room metadata (default: {})
  emptyTimeout?: number          // Close this long after it's no longer used, if nobody joined (ms; default: config.room)
  departureTimeout?: number      // Close this long after the last member left (ms; default: config.room)
}
```

- `Room.getOrCreate()` on an existing room ignores its `options`.
- `Room.setMeta()` replaces the room's metadata; `Room.setAttributes()` merges it by key (a key set to `undefined` is removed).
- `target` is `{ id }` for one membership, or `{ identity }` for every membership of a user. `Room.removeParticipant()` takes the reason in it: `{ id, reason }` or `{ identity, reason }`.
- `Room.getParticipants(id, { identity })` returns one user's memberships: use it to check whether a user is online.
- Typed generics: `Room.get<RoomMeta, MemberMeta, Message>(id)`. The two metadata types are unchecked; the message type is checked (see <Link href="#typescript" />). `Room.list<RoomMeta>()` types each `RoomInfo.meta`.

### `Room`

| Method | Description |
|---|---|
| `join(options?)` | Join; returns your `LocalParticipant`. Options: `{ meta?, selfDelivery?, identity?, hidden? }` (`identity` and `hidden` are server-side only). |
| `getParticipants(options?)` / `getParticipant(id)` | The members / one member (or `null`). Server-side, `{ hidden: true }` returns the <Link href="#hidden-participants">hidden participants</Link> instead. |
| `subscribe(cb)` | Every member's messages: `(data, info, from)`. Returns an unsubscribe function. |
| `subscribeBinary(cb, { track? }?)` | Every member's binary frames, optionally one track. `info` carries `track` and `meta`. |
| `onJoin(cb)` / `onLeave(cb)` | A member joined / left: `(member)` / `(member, cause)`. |
| `onParticipantUpdate(cb)` | A member's metadata changed: `(member, meta, prev)`. |
| `onUpdate(cb)` | The room's metadata changed: `(meta, prev)`. |
| `onAnnounce(cb)` | `Room.announce()` messages: `(data, info)`. |
| `onEmpty(cb)` / `onClose(cb)` | The last member left / the room closed (on the client, also when the client is disconnected). |
| `onChange(cb)` / `snapshot()` | Something changed / an immutable view, for `useSyncExternalStore()`. |

Read-only: `id`, `meta`, `count`, `isEmpty`, `isClosed`.

### `LocalParticipant`

Returned by `join()`. It receives only the private messages sent to you; room-wide messages arrive on the room and on each `RemoteParticipant`.

| Method | Description |
|---|---|
| `publish(data, { coalesce?, retain? }?)` | Publish to the whole room. |
| `publishBinary(data, { track?, meta?, retain? }?)` | Publish binary. Its receipt's `receivers` is `0` when nobody subscribes to the track. |
| `send(to, data)` | Send a private message to a participant (or its `id`). Resolves with `{ seq, timestamp }`. |
| `send(to, data, { ack: true })` | Resolves with `{ response, seq, timestamp }` once the recipient's `listen()` handler returned. |
| `listen(cb)` | Receive private messages: `(data, from)`, with `from === null` for the room's own. Return a value to reply to `{ ack: true }`; `throw Abort(value)` to reject it. |
| `setMeta(meta)` / `setAttributes(partial)` | Replace / merge your metadata. |
| `onDemand(cb)` | `(track, wanted)`: whether anyone watches a track of yours. |
| `leave()` / `onLeave(cb)` | Leave / your own departure: `cause.type` is `'left'`, `'removed'`, `'closed'`, or `'disconnected'`. |

Read-only: `id`, `meta`, `identity`, `selfDelivery`.

### `RemoteParticipant`

Another member, seen through a room.

| Method | Description |
|---|---|
| `subscribe(cb)` / `subscribeBinary(cb, { track? }?)` | This member's messages / binary frames. |
| `onUpdate(cb)` / `onLeave(cb)` | This member's metadata changed / this member left. |

Read-only: `id`, `meta`, `identity`, `joinedAt`.

### Senders

Every message callback receives its sender as `from`: `{ id, meta, identity }`, set by the server. `from === null` means the room itself sent it.
