`Room` gives you multi-party **rooms**: who's in the room, messages to everyone or to one participant, audio/video tracks, and moderation. Use it for chat, game lobbies, collaborative editing, and live dashboards.

> **Needs a long-running server**, as <Link href="/channel">channels</Link> do: Room doesn't work on serverless platforms that enforce a short time limit on connections, such as Vercel or AWS Lambda. On Cloudflare Workers, see <Link href="/stream/cloudflare" />.

> When you only need a pipe to one client, use <Link href="/channel#new-channel">`new Channel()`</Link>. When you need pub/sub without membership, use <Link href="/channel#new-broadcastchannel">`new BroadcastChannel()`</Link>.


## Install

```bash
npm install @telefunc/room
```

> Room runs on Telefunc, so your app also needs `telefunc` installed, and one of its plugins for the client code below to import a `.telefunc.js` file: see <Link href="/vite-plugin" /> or <Link href="/install" />.

Then load Room's client code before your client receives a room, for example in your client entry:

```js
// Environment: client

import '@telefunc/room/client'
```

> Telefunc's Vite, webpack, Next.js and Babel plugins add this import for you when `@telefunc/room` is in the `package.json` at your app's root. A dependency declared elsewhere, such as only in `deno.json`, isn't found: keep the import.

> The server needs no extra import: importing `Room` from `@telefunc/room` loads it.

> On Cloudflare, use <Link href="/vite-plugin">Telefunc's Vite plugin</Link>. When `@telefunc/room` isn't in your `package.json`, also add `import '@telefunc/room/server'` to your Worker's entry, as a Durable Object can get Room's calls before any of your telefunctions loaded `Room`.


## Create and join a room

A telefunction returns the room, and the client joins it:

```js
// Lobby.telefunc.js
// Environment: server

import { Room } from '@telefunc/room'

export async function onGetLobby() {
  const room = await Room.getOrCreate('lobby')
  Room.guard(room, { anyoneCanJoin: true })
  return room
}
```
```js
// Lobby.js
// Environment: client

import { onGetLobby } from './Lobby.telefunc'

const room = await onGetLobby()

room.onJoin((member) => console.log(`${member.meta.name} joined`))
room.subscribe((message, { from }) => console.log(from ? `${from.meta.name}: ${message.text}` : message.text))

const me = await room.join({ meta: { name: 'Alice' } })
await me.publish({ text: 'hello' })
```

`join()` returns your participant, `me`. For all of this as an app that runs as is, see <RepoLink path="/examples/room" />.

A client joins only a room whose telefunction says who may: `anyoneCanJoin: true` lets anyone in, and an `onBeforeJoin()` hook decides per join (see <Link href="#control-who-can-join-and-post" />). Without either, `room.join()` on the client is refused.

> `meta` is what a participant shows about itself, such as its name. A room has a `meta` too: set it with `Room.create('lobby', { meta: { topic: 'General' } })`, and read it on the client with `room.meta`.

Every page that has the room open receives its participants and each change to them, so join only the people who take part. A page that only watches, such as a match's audience, takes the room its telefunction returns and doesn't join it: it reads `room.getParticipants()` and `room.count`, and its `subscribe()` listeners receive the room's messages. Nobody sees it among the participants, and it can't publish or send a message: those are methods of `me`, the participant `join()` returns.


## Show who's in the room

```js
// Environment: client

const update = () => renderMembers(room.snapshot().participants)
update()
room.onChange(update)
```

`room.onChange()` fires whenever anything `room.snapshot()` shows changes: someone joins, leaves, changes their `meta`, or loses and regains their connection, or the room's `meta` changes. `room.snapshot()` returns the whole room in one value.

In React:

```jsx
// Environment: client

import { useSyncExternalStore } from 'react'

function Members({ room }) {
  const { participants, count } = useSyncExternalStore(room.onChange, room.snapshot)
  return <>{count} online: {participants.map((p) => <Avatar key={p.id} {...p.meta} />)}</>
}
```

Each participant of `room.snapshot()` is that participant as of the snapshot: it has the participant's methods, and its fields stay as they were. A participant that changes is a new object in the next snapshot, and everyone else is the same object as before, so compare participants by `id`.

A participant whose page lost its connection stays in the room while it reconnects, with `isConnected: false`:

```jsx
// Environment: client

participants.map((p) => <Avatar key={p.id} {...p.meta} status={p.isConnected ? null : 'reconnecting…'} />)
```

To react to one event, use `room.onJoin()`, `room.onLeave()`, or a participant's `onDisconnect()` and `onReconnect()`. To follow one participant, use its `onChange()`.

Every listener (`onChange()`, `onJoin()`, `subscribe()`, `listen()`, …) returns a function that removes it, for example in a React effect's cleanup:

```jsx
// Environment: client

useEffect(() => room.subscribe((message) => addMessage(message)), [room])
```

On the server, `getContext()` throws inside a room's event and message listeners (`onJoin()`, `onChange()`, `subscribe()`, `listen()`, …), since they run for what other users do: read the context before you add them. The hooks you pass to `Room.guard()` aren't listeners: they run for the client the room is returned to (see <Link href="#control-who-can-join-and-post" />).

## Stop listening

Pass `{ signal }` to a listener registration to remove it when you abort the signal, or use `messages()` to iterate messages. Each message is `{ type, data, info }`: `type` is `'text'` or `'binary'`, and `data` and `info` are what a `subscribe()` or `subscribeBinary()` listener receives, with `info.from` the sender's `id`, `meta` and `identity` as they were when the message arrived:

```js
// chat.js
// Environment: client

const controller = new AbortController()
room.onJoin((participant) => console.log(participant.id), { signal: controller.signal })
for await (const message of room.messages({ signal: controller.signal })) {
  if (message.type === 'binary') showVideo(message.info.from.id, message.data, message.info.track)
  else console.log(message.info.from ? `${message.info.from.meta.name}: ${message.data.text}` : message.data.text)
  break
}
controller.abort()
```


## Update your name or status

```js
// Environment: client

await me.updateMeta({ status: 'away' })               // changes only `status`
await me.setMeta({ name: 'Alice', status: 'online' }) // replaces all of your meta
```

Everyone in the room sees the change. The `meta` you read is read-only, and freezing doesn't lock a `Map`, `Set`, `Date` or `Uint8Array` inside it, so build a new value to change any of it, as above.


## Send a message to everyone

```js
// Environment: client

room.subscribe((message, { from }) => showMessage(from?.meta.name, message.text))

await me.publish({ text: 'hello' })
```

`info.from` is the participant who sent the message, or `null` for one your server published (see <Link href="#send-from-the-server" />). A client can't fake it.

To receive the messages of one participant only, subscribe on that participant. `room.onJoin()` gives you the participants who join after you, and `room.getParticipants()` the ones already there:

```js
// Environment: client

const follow = (member) => member.subscribe((message) => showMessageFrom(member.meta.name, message.text))
for (const member of room.getParticipants()) follow(member)
room.onJoin(follow)
```

Every read of a room answers at once: `room.getParticipants()`, `room.getParticipant(id)`, `room.meta`, `room.count`, `room.isClosed` and `room.snapshot()`. A page's room arrives with its participants and stays current while the page is connected. On the server, a room is as of your `await Room.get()`, and stays current from then on while you listen to it or have joined it; once you stop, it stays as it was then. To read it again later, call `Room.get()` again.

> You also receive your own messages. To not receive them, join with `selfDelivery: false`, on the page (`room.join({ meta, selfDelivery: false })`) or on the server (`Room.join(id, { selfDelivery: false })`). For a participant your telefunction joins, that holds from the moment the telefunction returns it: a message published as it before then may or may not reach a room the page already has open, so don't rely on that message being shown, or not shown, on the page.

> `info.seq` numbers everyone's messages, your server's too, in one order for the whole room, so it jumps over the ones this page doesn't receive: its own with `selfDelivery: false`, or those of participants it doesn't subscribe to. It never jumps over a lost message: a page never misses a message on no track (see <Link href="#remove-a-participant" />).

> Each participant's messages arrive in the order it sent them. `info.from` is that participant as the room knows it when the message arrives, so `info.from.meta` is its meta then, not when it sent the message. Joins, leaves and meta changes arrive in the same order everywhere, but two pages can see a message and someone else's join in a different order.

For updates that change many times per second, such as a mouse cursor, publish on a track with `lossy: true`: a page that falls behind skips to the newest one, and its `info.seq` jumps over the ones it skipped.

```js
// Environment: client

onCursorMove((position) => me.publish(position, { track: 'cursor', lossy: true }))
room.subscribe((position, { from }) => drawCursor(from.id, position), { track: 'cursor' })
```

> In `publish()`, `lossy` needs a `track`: a message on no track reaches everyone, in the room's order, and is never skipped. `publishBinary()` without a `track` publishes on the track `'main'`, which takes `lossy` like any other track.


## Check the message type

Pass your types to `Room.get()`, `Room.create()` or `Room.getOrCreate()`:

```ts
// Chat.telefunc.ts
// Environment: server

import { Room } from '@telefunc/room'

type RoomMeta = { topic: string }
type MemberMeta = { name: string }
type Message = { text: string }

export async function onGetChat(roomId: string) {
  return await Room.get<RoomMeta, MemberMeta, Message>(roomId)
}
```

`publish()` and `subscribe()` are then typed with `Message`, and Telefunc checks every message a client publishes against it, as it checks telefunction arguments (see <Link href="/shield" />): a message of another shape is rejected with `ShieldValidationError`.


## Send a private message

```js
// Environment: client

me.listen((message, { from }) => showPrivateMessage(from?.meta.name, message))

await me.send(member, 'meet me in room 2') // `member` from room.onJoin() or room.getParticipants()
```

Only the recipient receives it.

To get a reply, pass `{ ack: true }`. The recipient's `listen()` callback returns the reply:

```js
// Environment: client

// Alice
me.listen((move) => (isLegal(move) ? 'ok' : 'illegal'))

// Bob
const reply = await me.send(alice, { move: 'e4' }, { ack: true })
console.log(reply) // 'ok'
```

A callback that returns `undefined` only observes, so it can stand beside the one that replies. If two callbacks return a value, `send()` rejects.

> A private message is delivered at most once: when it can't be handed on to the recipient, `send()` rejects, and the message isn't sent again. `publish()` is at most once too, <Link href="/channel#delivery">like Broadcast's</Link>. Room logs on your server each message, join or leave it knows it couldn't hand on.


## Send from the server

```js
// Environment: server

import { Room } from '@telefunc/room'

await Room.publish('lobby', { type: 'maintenance', in: '5min' })    // to everyone
await Room.send('lobby', { identity: userId }, { badge: 'winner' }) // to every tab of one user
```
```js
// Environment: client

room.subscribe((message, { from }) => {
  if (from === null) showBanner(message) // published by the server
})
me.listen((message, { from }) => {
  if (from === null) showSystemMessage(message) // sent by the server
})
```

Sending to `{ identity }` works when the server joined the user with that `identity`, as in <Link href="#control-who-can-join-and-post" />. To send to one participant, pass `{ id }`.


## Control who can join and post

Call `Room.guard()` in the telefunction that returns the room, and throw <Link href="/Abort">`Abort()`</Link> to reject a join, a message, or a private message:

```js
// Chat.telefunc.js
// Environment: server

import { Abort, getContext } from 'telefunc'
import { Room } from '@telefunc/room'

export async function onJoinChat(roomId) {
  const { user } = getContext()
  const room = await Room.getOrCreate(roomId)
  Room.guard(room, {
    onBeforePublish: (from, message) => {
      if (isSpam(message)) throw Abort('spam')
    },
    onBeforeSend: async (from, to) => {
      if (!(await areFriends(user.id, to.identity))) throw Abort('not friends')
    },
  })
  if (isBanned(user.id)) throw Abort('banned')
  const me = await room.join({ meta: { name: user.name }, identity: user.id })
  return { room, me }
}
```
```js
// Chat.js
// Environment: client

import { onJoinChat } from './Chat.telefunc'

const { room, me } = await onJoinChat('general')
try {
  await me.publish({ text: 'buy now!!!' })
} catch (err) {
  console.log(err.abortValue) // 'spam'
}
```

With no `onBeforeJoin()` and no `anyoneCanJoin`, the client can't call `room.join()` itself: users join only through `onJoinChat()`, as themselves. `identity` is your user id, set by the server at `join()`. Every message carries its sender's `identity` (`info.from.identity`), and a client can't change it.

<Warning>Check permissions on `identity`, never on `meta`: a client can set its `meta` to anything.</Warning>

The hooks run for the client this telefunction returns the room to, so `user` in them is that client's user.

To run code after a join or a message, such as saving the message, use `onAfterJoin()`, `onAfterPublish()` and `onAfterSend()` (see <Link href="#load-chat-history" />).


## Remove a participant

```js
// Moderation.telefunc.js
// Environment: server

import { Abort, getContext } from 'telefunc'
import { Room } from '@telefunc/room'

export async function onRemove(roomId, participantId) {
  const { user } = getContext()
  if (!user.isModerator) throw Abort()
  await Room.removeParticipant(roomId, { id: participantId, reason: 'be nice' })
}
```
```js
// Environment: client

await onRemove(room.id, member.id) // `member` from room.getParticipants() or room.onJoin()
```

To remove every tab of a user, pass their `identity`: `Room.removeParticipant(roomId, { identity: userId, reason: 'banned' })`.

The removed participant learns why:

```js
// Environment: client

me.onLeave((cause) => {
  if (cause.type === 'removed') showBanner(`Removed: ${cause.reason}`)
  if (cause.type === 'disconnected') rejoin() // automatic reconnection gave up: call the telefunction that returned the room again
})
```

The removed participant's page stops receiving the room: `room.isClosed` is `true` and `room.onClose()` runs with the removal's cause, unless the page holds another participant of the room. A page that never joined keeps receiving.

> Removing doesn't keep anyone out: a telefunction that returns the room again lets them back in. Refuse them there, or in `onBeforeJoin()` (see <Link href="#control-who-can-join-and-post" />).

A page that falls behind what the server can hold for it gets `'disconnected'`. It never misses a message, a join, a leave, a `meta` change or a frame, except a frame published with `lossy: true`, where it skips to the newest frame (see <Link href="#stream-audio-or-video" />).


## Run a game loop or a bot on the server

Create the room and join it from the server with `{ hidden: true }`, for example in the telefunction that starts a match:

```js
// Match.telefunc.js
// Environment: server

import { Room } from '@telefunc/room'

export async function onStartMatch() {
  const matchId = crypto.randomUUID()
  const room = await Room.create(matchId, { emptyTimeout: Infinity, departureTimeout: Infinity }) // open until Room.close()
  const host = await room.join({ identity: 'host', hidden: true })
  const game = createGame()
  host.listen((command) => game.apply(command))     // commands from players
  const loop = setInterval(() => host.publish(game.state()), 50) // state to everyone
  room.onClose(() => clearInterval(loop))
  game.onEnd(() => Room.close(matchId)) // ends the match, and the loop with it
  return matchId
}
```

> A page that falls behind gets every message, so state it may skip goes on a track, published with <Link href="#stream-audio-or-video">`lossy: true`</Link>, where it skips to the newest frame.

A hidden participant can do everything a participant does, but players don't see it among the room's participants.

To let players send it commands, return it with the room:

```js
// Match.telefunc.js
// Environment: server

import { Abort, getContext } from 'telefunc'
import { Room } from '@telefunc/room'

export async function onJoinMatch(matchId, name) {
  const { user } = getContext()
  const room = await Room.get(matchId)
  const host = room.getParticipants({ hidden: true }).find((p) => p.identity === 'host')
  if (!host) throw Abort('no host')
  const me = await room.join({ meta: { name }, identity: user.id })
  return { room, me, host }
}
```
```js
// Match.js
// Environment: client

import { onJoinMatch } from './Match.telefunc'

const { room, me, host } = await onJoinMatch(matchId, 'Alice')
room.subscribe((state, { from }) => {
  if (from?.identity === 'host') render(state)
})
await me.send(host, { type: 'move', to: 'e4' })
```

## Stream audio or video

Publish each source on its own track, and subscribe to the tracks you show:

```js
// Environment: client

// The participant who films
// encodeCamera(): your encoder, e.g. WebCodecs' VideoEncoder
// live video: don't await, or each frame waits a round trip for the previous one
encodeCamera((frame, isKeyframe) =>
  me.publishBinary(frame, { track: 'camera', meta: { isKeyframe }, retain: isKeyframe, lossy: true }),
)

// The participants who watch; showVideo(): your decoder, e.g. WebCodecs' VideoDecoder
const watch = (member) =>
  member.subscribeBinary((frame, info) => showVideo(member.id, frame, info.meta.isKeyframe), { track: 'camera' })
for (const member of room.getParticipants()) watch(member)
room.onJoin(watch)
```

With `retain: isKeyframe`, a viewer who arrives mid-stream starts from the last keyframe, see <Link href="#give-late-joiners-the-current-state" />.

On a track, `info.seq` counts its sender's frames on that track. A viewer that falls behind gets every frame, and gets `'disconnected'` where the server can't hold them for it. Where only the newest frame matters, such as a position or live audio and video, pass `lossy: true` in each publish on its track: a viewer that falls behind then skips to the newest frame, and its `info.seq` jumps over what it skipped:

```js
// Environment: client

// onCursorMove(), onStroke(): your app's input events, each giving a Uint8Array
onCursorMove((position) => me.publishBinary(position, { track: 'cursor', lossy: true })) // may be skipped
onStroke((stroke) => me.publishBinary(stroke, { track: 'drawing' })) // a viewer never misses one
```

> Each publish says `lossy` itself. A publish without it is never skipped, and on a track it arrives after the lossy ones published before it, so a cursor's last position or a stroke's end can follow its lossy updates on the same track.

With `lossy: true`, a viewer can skip a video frame that later frames depend on, so number the frames in `meta` (a frame replaced on its way to the server never gets an `info.seq`) and, at a gap, drop frames until the next keyframe and restart your decoder from it.

To send frames only while someone watches, read `me.demand`, the tracks of yours that someone receives now, sorted by track name, and follow it with `me.onChange()`:

```js
// Environment: client

let watched = false
function follow() {
  watched = me.demand.some((demand) => demand.track === 'camera')
}
follow()
me.onChange(follow)
// live video: don't await, or each frame waits a round trip for the previous one
encodeCamera((frame, isKeyframe) => {
  if (watched) me.publishBinary(frame, { track: 'camera', meta: { isKeyframe }, retain: isKeyframe, lossy: true })
})
```

> A viewer of every track, `subscribeBinary()` without `track`, receives a track from its first publish on.

Each entry also says who receives the track: `watchers`, the people at the pages and server-side rooms receiving it, in the order `room.getParticipants()` lists them, and `watcherCount`, everyone receiving it. A page or a server-side room that receives it with nobody to list, such as a page that didn't join, counts one. You are never listed, and neither is a hidden participant:

```js
// Environment: client

function watchingLine({ watchers, watcherCount }) {
  const names = watchers.map((participant) => participant.meta.name).join(', ')
  const more = watcherCount - watchers.length
  if (watchers.length === 0) return `${watcherCount} watching`
  return more > 0 ? `watching: ${names} and ${more} more` : `watching: ${names}`
}
function showWatching() {
  const camera = me.demand.find((demand) => demand.track === 'camera')
  caption.textContent = camera ? watchingLine(camera) : ''
}
showWatching()
me.onChange(showWatching)
```

`me.demand` stays the same array, and each entry the same object, until it changes, so `useSyncExternalStore(me.onChange, () => me.demand)` reads it in React.

> Audio works the same way, on its own track such as `{ track: 'mic' }`.

> For video calls with many participants, or video streamed to an audience, use a WebRTC SFU for the video, and a room for the chat and signaling. See [telefunc#449](https://github.com/telefunc/telefunc/issues/449).


## Give late joiners the current state

Publish with `retain: true`, and a room that starts listening later receives that message before any new ones:

```js
// Environment: client

// keyframe: a Uint8Array from your encoder, e.g. WebCodecs' VideoEncoder
await me.publish({ phase: 'voting' }, { retain: true })
await me.publishBinary(keyframe, { track: 'camera', meta: { isKeyframe: true }, retain: true, lossy: true })
```

A late joiner gets the last retained message, and each participant's last retained frame on each track, as long as its publisher is in the room. For state that outlives the participants, such as a game phase, publish it from a <Link href="#run-a-game-loop-or-a-bot-on-the-server">hidden participant</Link>.

Adding another listener while the same room is already listening to that publisher or track doesn't replay its retained message or frame. A second component that needs it calls a telefunction that returns `Room.get(id)` and subscribes on the result, without joining.


## Load chat history

Save each message in `onAfterPublish()`, and return the history with the room:

```js
// Chat.telefunc.js
// Environment: server

import { getContext } from 'telefunc'
import { Room } from '@telefunc/room'

export async function onJoinChat(roomId) {
  const { user } = getContext()
  const room = await Room.getOrCreate(roomId, { tail: true }) // the client also gets the messages published after the history you load
  Room.guard(room, {
    onAfterPublish: async (from, message, info) => {
      await db.messages.insert({ ...message, roomId, authorId: user.id, seq: info.seq })
    },
  })
  const history = await db.messages.latest(roomId, 50) // ordered by seq
  const me = await room.join({ meta: { name: user.name }, identity: user.id })
  return { room, me, history }
}
```
```js
// Chat.js
// Environment: client

import { onJoinChat } from './Chat.telefunc'

const { room, me, history } = await onJoinChat('lobby')

const shown = new Set(history.map((message) => message.seq))
for (const message of history) render(message)
room.subscribe((message, info) => {
  if (!shown.has(info.seq)) render(message) // skip what history already shows
})

await me.publish({ text: 'hello' }) // saved by onAfterPublish()
```

> Add your other hooks, such as the ones in <Link href="#control-who-can-join-and-post" />, to this same `Room.guard()` call.


## Leave a room

```js
// Environment: client

await me.leave()
```

Everyone else's `room.onLeave()` fires.


## Close a room

```js
// Environment: server

import { Room } from '@telefunc/room'

await Room.close('lobby')
```

A room also closes by itself a while after nobody is in it and no page has it open, see <Link href="/room-config" />.

To keep a room open until you call `Room.close()`, create it with:

```js
// Environment: server

await Room.create('match-42', { emptyTimeout: Infinity, departureTimeout: Infinity })
```

`room.onClose((cause) => {})` fires when the room closes, with `cause.type` `'closed'`. A page's room also closes when its connection is gone for good, with `'disconnected'`, and when the page's last participant of it was removed, with `'removed'` and the removal's `reason`.

import IORedis from 'ioredis'

## Methods

### `Room.*`

Server-side.

| Method | Description |
|---|---|
| `Room.create(id, options?)` | Create a room. Throws if it exists. |
| `Room.get(id, { tail? }?)` | Read a room: as it is now, and current from then on while you listen to it or have joined it. Throws if it doesn't exist. With `tail: true`, the client also gets the messages published after the history you load (see <Link href="#load-chat-history" />). |
| `Room.getOrCreate(id, { ...options, tail? }?)` | Get a room, or create it. `tail` as for `Room.get()`. |
| `Room.guard(room, hooks)` | Add `onBefore*()` and `onAfter*()` hooks to a room, once, and say who may join it from the client. |
| `Room.join(id, { meta?, selfDelivery?, identity?, hidden? }?)` | Join a room from the server, without getting the room first. |
| `Room.list({ prefix? }?)` | List the open rooms. |
| `Room.setMeta(id, meta)` / `Room.updateMeta(id, meta)` | Replace / update the room's `meta`. |
| `Room.getParticipants(id, { identity? }?)` | List the participants, or one user's: each `{ id, identity, meta, joinedAt, isConnected }`, with no methods. |
| `Room.publish(id, message)` | Send to everyone: `room.subscribe()` gets it with `info.from` `null`. Resolves to `{ seq, timestamp }`. |
| `Room.send(id, target, message)` | Send to one participant (`{ id }`) or to every tab of a user (`{ identity }`). Resolves to `{ seq, timestamp }`, or for `{ identity }` to a list of them, one per tab it reached. |
| `Room.removeParticipant(id, target)` | Remove a participant (`{ id, reason? }`) or every tab of a user (`{ identity, reason? }`). |
| `Room.close(id)` | Close a room. |

`options` is `{ meta? }`, and the timeouts of <Link href="/room-config" />.

### `room`

| Method | Description |
|---|---|
| `join({ meta?, selfDelivery? }?)` | Join; returns your participant. |
| `join({ meta?, identity?, hidden? })` | Server-side: join with a user id, or as a <Link href="#run-a-game-loop-or-a-bot-on-the-server">hidden participant</Link>. |
| `snapshot()` / `onChange(cb)` | The whole room, `{ id, meta, count, isClosed, participants }` with each participant as of the snapshot / called when it changed, once for the changes of one task. |
| `getParticipants()` | The participants. |
| `getParticipant(id)` | One participant, or `null`. |
| `getParticipants({ hidden: true })` | Server-side: the hidden participants. |
| `onJoin(cb)` / `onLeave(cb)` | Someone joined / left. |
| `subscribe(cb, { track? }?)` / `subscribeBinary(cb, { track? }?)` | Everyone's messages, the server's included, or those on `track` / binary frames: `cb(message, info)`, with `info` `{ seq, timestamp, from }`, plus `{ track, meta }` on a track; `from` is `null` for the server's. |
| `messages({ signal? }?)` | Everyone's messages and binary frames, to read with `for await`: each `{ type, data, info }`. |
| `onEmpty(cb)` / `onClose(cb)` | The last participant left / the room closed, with `cause.type`: `'closed'`, or on a page `'removed'` (the page's last participant of it was removed) or `'disconnected'`. |

Properties: `id`, `meta`, `count`, `isEmpty`, `isClosed`.

### `me`

| Method | Description |
|---|---|
| `publish(message, { track?, lossy?, retain? }?)` | Send to everyone. `lossy` needs `track`. |
| `publishBinary(data, { track?, meta?, retain?, lossy? }?)` | Send binary to everyone. Without `track`, on the track `'main'`. |
| `send(to, message, { ack? }?)` | Send to one participant. Resolves to `{ seq, timestamp }`, or with `ack: true` to its `listen()` reply. |
| `listen(cb)` | Receive private messages: `cb(message, { from })`; return a value to reply. |
| `setMeta(meta)` / `updateMeta(meta)` | Replace / update your `meta`. |
| `onChange(cb)` | Your `meta`, `isConnected` or `demand` changed; once for the changes of one task. |
| `leave()` / `onLeave(cb)` | Leave / you left, with `cause.type`: `'left'`, `'removed'`, `'closed'`, `'disconnected'`, or `'unknown'` (it left while nothing here listened to the room, too long ago to know why). |
| `onDisconnect(cb)` / `onReconnect(cb)` | Your connection to the room dropped / is back. |

Properties: `id`, `meta`, `identity`, `selfDelivery`, `isConnected`, and `demand`: the tracks of yours someone receives now, each `{ track, watchers, watcherCount }`.

### Other participants

| Method | Description |
|---|---|
| `subscribe(cb, { track? }?)` / `subscribeBinary(cb, { track? }?)` | This participant's messages, or those on `track` / binary frames: `cb(message, info)`, as on `room`. |
| `onChange(cb)` / `onLeave(cb)` | This participant's `meta` or connection changed / this participant left. |
| `onDisconnect(cb)` / `onReconnect(cb)` | This participant's connection dropped / is back. |

Properties: `id`, `meta`, `identity`, `joinedAt` (Unix epoch milliseconds), `isConnected`.

### `Room.guard()` hooks

| Hook | Description |
|---|---|
| `anyoneCanJoin` | `true`: any client may join. Without it or `onBeforeJoin()`, a client's `room.join()` is refused. |
| `onBeforeJoin(member)` | Before a join. Throw `Abort()` to reject it. |
| `onBeforePublish(from, message, { track })` | Before a message or a binary frame to everyone, `track` being `null` for a message on no track. Throw `Abort()` to reject it. |
| `onBeforeSend(from, to, message)` | Before a private message. Throw `Abort()` to reject it. |
| `onAfterJoin(member, { joinedAt })` | After a join. |
| `onAfterPublish(from, message, { seq, timestamp, track })` | After a message or a binary frame to everyone. |
| `onAfterSend(from, to, message, { seq, timestamp })` | After a private message. |
